### root-cause-argocd-excludes-endpoints · root-cause · ArgoCD's resource.exclusions skip Endpoints cluster-wide, so the chart's static kubeEtcd Endpoints object is never applied

The #762 design supplies kubeEtcd.endpoints, which makes victoria-metrics-k8s-stack render a selector-less Service plus a static Endpoints object. apps/argocd/values.yaml:128 sets resource.exclusions, reproducing the argo-cd chart defaults because Helm does not merge that multiline string, and its first entry excludes apiGroups ['', discovery.k8s.io] kinds [Endpoints, EndpointSlice]. ArgoCD therefore renders the Endpoints object and silently drops it, surfacing only as app condition ExcludedResourceWarning: 'Resource /Endpoints victoria-metrics-victoria-metrics-k8s-stack-kube-etcd is excluded in the settings'. The app still reports Synced/Healthy. The Service is NOT excluded, so it moved to 2381 and lost its selector, and nothing will ever populate its Endpoints. Why CI missed it: helm template renders the Endpoints object correctly, and test_etcd_scrape.py asserted the render, not whether ArgoCD applies that kind. #762's plan and spec never mention ArgoCD exclusions. Fix (operator-chosen): scrape via a VMStaticScrape, a kind ArgoCD applies, with kubeEtcd disabled. A server-side dry-run of that VMStaticScrape was accepted.
